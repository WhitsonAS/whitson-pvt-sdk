# Agent Notes

Start by reading the relevant existing module before changing behavior. Keep edits narrow and aligned with nearby patterns.

## Commands

- Setup: `uv sync`; install the task runner with `uv tool install rust-just` if `just` is missing.
- Dependency cooldown: `[tool.uv] exclude-newer = "3 days"` in `pyproject.toml`, as in the API repository, so `uv lock` never picks a release younger than three days; add a per-package exception only when a fix is required, and say why.
- Focused checks: `just lint`, `just ty`, `just build`.
- `just lint` runs Ruff over `whitson_pvt_sdk/`, `tests/`, `scripts/` and `examples/` with the API repository's rule set (`pyproject.toml`, `[tool.ruff.lint]`) plus `W`; `T201` keeps `print` to `scripts/`, `examples/` and the integration tests, and a `noqa` needs its reason on the line. Fix the code rather than ignoring a rule; generated code gets per-file ignores, never hand edits.
- `just check` runs `lint -> format -> ty`; it is not read-only because `format` runs `ruff format whitson_pvt_sdk/`.
- `just all` regenerates models, applies lint fixes/formatting, typechecks, then builds.

## Tests

- Tests follow the API repository's `TESTING.md`: each proves a behaviour through the public interface and fails when it breaks; no tests that restate generated models or the generator's output, copy an implementation, or duplicate a contract proven at its owning layer.
- Mock only at boundaries. Lint bans `unittest.mock` and `pytest_mock` (`TID251`), and `just lint` covers `tests/`: use `httpx2_mock` for HTTP and `monkeypatch` for the clock and OS calls, never for an SDK function.
- HTTP is mocked with `httpx2-pytest` (the `pytest-httpx` API for httpx2): request the `httpx2_mock` fixture. It patches httpx2's transports, so a test that requests it cannot also reach the loopback server `tests/test_cli_mcp.py` starts.
- Run the test suite with `just test`; it executes `uv run pytest tests/ -v`.
- Run coverage with `just test-cov`; it executes `uv run pytest tests/ -v --cov=whitson_pvt_sdk --cov-report=term-missing`.
- Prefer `just test` over invoking pytest directly unless you are intentionally running a focused subset.

## Codegen

- Treat `whitson_pvt_sdk/_generated/**` and `whitson_pvt_sdk/v2/models/__init__.py` as generated output.
- Regenerate from the external API's OpenAPI document, either from a file or from a live API:
  - From a file, with no API running: `just generate-file FILE`, or `just generate-file-check FILE` to only show the diff. In a whitsonPVT workspace the file is `../app/api/openapi-external.json`, which the app repository commits and keeps current.
  - From a live local API at `http://localhost:4000`: `just generate`, which fetches `http://localhost:4000/external/{version}/docs/openapi.json`.
  - The version is an optional last argument of every generate recipe (`just generate-file FILE v2`); without it the generator uses `LATEST_VERSION`. The supported versions are the `Version` literal in `scripts/sdk_generator/models.py`, and `LATEST_VERSION` in `config.py` is its last member; the justfile names no version.
- The repo-specific generator lives in `scripts/sdk_generator/`. It runs `ruff check --fix --select I,F401` and `ruff format` on rendered endpoint/resource files, so generated files should not require a second formatting pass.
- Put hand-maintained shared models in `whitson_pvt_sdk/shared/models.py`; avoid hand-editing generated files unless intentionally patching generated output when the API spec is unavailable.
- Authentication is excluded from generated resources via `EXCLUDED_RESOURCES`; keep auth as transport infrastructure, not as `client.authentication`.

## Working in a whitsonPVT workspace

- A whitsonPVT development workspace can hold this repository as an optional `sdk/` worktree next to `app/` and `utils/` (`mise create NAME --sdk` in the app repository). Its branch starts from `origin/main` and tracks nothing until pushed.
- Commit, push and release from `sdk/` as usual; this file and its commit-message rules apply there.
- There are no workspace tasks for the SDK: run this repository's `just` recipes in `sdk/` (`mise exec -- just RECIPE` outside a mise-activated shell). The workspace presets `WHITSON_INTEGRATION_BASE_URL` and, unless one is exported, `WHITSON_INTEGRATION_TOKEN` (the API's local bypass token), so `just integration` targets the workspace API; start that with `EXTERNAL_API_AUTH_BYPASS=true mise api:dev`. It writes test data to the workspace database, so ask first.
- Never work in the persistent clone the workspaces share (`PVT_SDK_SOURCE`, default `~/Developer/whitson-pvt-sdk`); it stays on `main`.

## Architecture

- Public entrypoint is the `WhitsonPVTClient` class (`whitson_pvt_sdk/_client.py`, re-exported from `whitson_pvt_sdk`); it resolves the credential and wires the v2 resources. Only external API v2 is supported; v1 was removed in 2.0.
- Credentials, each in one module with a small interface (`a -> b` means a imports b):
  - `whitson_pvt_sdk/credentials.py`: the credential kinds, `ApiToken` and `StoredLogin` (frozen, `SecretStr`), `Credential = ApiToken | StoredLogin`, URL normalisation and the origin comparison used for host binding. Host checks and every host shown to the user go through `host_name` (the lowercase IDNA ASCII form), never `httpx2.URL.host`, which shows any punycode label as Unicode and so would hide a lookalike host in a confirmation and let `xn--` labels past `_trust.host_trust`.
  - `whitson_pvt_sdk/auth.py -> _refresh, _store, _trust`: `resolve_base_url` (`base_url` -> `WHITSON_PVT_URL` -> default login), returning `UrlFromArgument | UrlFromEnvironment | UrlFromDefaultLogin`, and `resolve_credential(base_url, token)`, which resolves the URL itself and then the credential (`token=` -> `WHITSON_PVT_TOKEN` -> stored login for that URL), returning `FromArgument | FromEnvironment | FromStore`, each carrying the `url`. An API token is used only with an explicit URL: with `UrlFromDefaultLogin` it raises `ConfigurationError` (one `match` on the URL source), so an environment token never goes to whatever the default login is, and only with a URL that passes `_trust.is_secure_url` (https, or http to a loopback host), so it is never sent in cleartext to another machine; `BearerSource`, with one `match` arm per credential kind; and `CredentialAuth`, the `httpx2.Auth` over it. The `StoredLogin` arm refuses any request whose scheme, host and port differ from the login's URL, renews within five minutes of expiry and once on a 401. A new credential kind is a new model in `credentials.py` plus one arm in each `BearerSource` method and in `resolve_credential`.
  - `whitson_pvt_sdk/_store.py`: the only code that knows the backend (`credentials.json` at 0600, the optional OS keyring, the `credentials.lock` file lock). Reads are lock-free snapshots (`get`, `default_url`); every write goes through `transaction()`, which holds the lock and persists on exit. Entries are `ActiveLogin | InvalidLogin`. The lock wait, `LOCK_TIMEOUT_SECONDS`, is derived from `_oauth.HTTP_TIMEOUT_SECONDS` so it outlasts a refresh held under the lock; running out raises `CredentialStoreBusyError` (exit 1, "try again"). The file is replaced with `os.replace`, retried briefly on `PermissionError` (Windows refuses while another process reads it) and then reported as `ConfigurationError`. A keyring that fails on read raises `ConfigurationError` naming the error; `remove()` deletes keyring entries itself and reports `keyring` (`not_used | deleted | not_deleted`) in `RemovedLogin`, which `logout` passes on in `LoggedOut`.
  - `whitson_pvt_sdk/_refresh.py -> _oauth, _store`: `usable_login` and `replace_access_token` return `Usable | NoLongerValid`; renewal re-reads the store under the lock, so a login renewed by another process is used without a token request, and `invalid_grant` marks the entry invalid. Plain functions, so `wpvt mcp` can get a current access token without going through an `httpx2.Auth`.
  - `whitson_pvt_sdk/_oauth.py`: the OAuth/OIDC wire protocol (`/external/v2/auth/config`, discovery, token, revocation requests) as Pydantic models; no state. Any 4xx with a well-formed OAuth `error` body is a refusal (`TokenRefused`; Auth0 sends `slow_down` as 429 and `authorization_pending`/`access_denied` as 403); a 5xx, a 4xx without one, or a success with a body of the wrong shape is `APIError` (exit 4, never `RequestRefusedError`, so a script does not skip records past a broken login server), except an http endpoint where https is required (`_trust.InsecureUrlError`), which is a `LoginError`.
  - `whitson_pvt_sdk/_trust.py`: which deployments a login may start for and where it may sign in, as pure functions. `host_trust` returns `TrustedDeployment | TrustedLoopback | TrustedByOverride` from the one `ALLOWLIST` (HTTPS under `pvt.whitson.com`, loopback hosts) and the explicit `trust_host` override, and raises `ConfigurationError` for any other host. A name under `localhost` is loopback only if every address the `resolve` argument returns for it is a loopback address (`login` passes `socket.getaddrinfo`; `localhost` and literal addresses are not looked up). `login_decision(trusted_host, issuer, audience, remembered)` returns `Proceed | FirstUse | IssuerChanged | AudienceChanged` from the host kind, `KNOWN_ISSUERS` (exact issuer hosts, today `whitson.eu.auth0.com`), whether the audience is the deployment's own `/mcp` URL (same origin, exact path) and `Remembered`, the issuer and audience of the stored login for that URL (`CredentialStore.remembered`, read from the profile without its tokens): a deployment with a known issuer and its own audience proceeds, one with another issuer or another audience raises `LoginError` with no override, and loopback (unless known issuer and own audience) and override hosts ask on first use, a changed issuer or a changed audience, each question carrying `foreign_audience` when the audience is not the deployment's own. `is_secure_url` (https, or http to a loopback host) is the one rule behind `SecureUrl`, the type for the issuer and its endpoints, and behind the API token check in `auth`. No environment variable or setting widens either list.
  - `whitson_pvt_sdk/login.py -> _oauth, _store, _trust`: `login(base_url, BrowserLogin(...) | DeviceLogin(), output=..., verify=..., scopes=AllScopes() | ChosenScopes(names=...) | PickScopes(ask=...), confirm=..., trust_host=...)`, `logout(base_url)` and `logout_all()`; `__all__` lists the public names. The only code that starts a login; library code never calls it. Order: host trust (no request on refusal), `/auth/config`, the login decision (refusals raise here), the device-login gate, the scope choice resolved against the advertised scopes (`READ_SCOPES`, `"read"`, stands for every `*:read` one; an unknown name is a `ConfigurationError`), the confirmation, then discovery and the flow; `PickScopes` defers the choice (an internal `_Picker`): `DeviceLogin` calls `ask` with the offered scopes before requesting the code (the CLI's `ask` prompts, or raises without a terminal), `BrowserLogin` shows a picker page; either answer goes through the same `_chosen_scopes` as `ChosenScopes`. `offline_access` is always added and the requested scopes are what `StoredLogin.scopes` keeps (the CLI compares them with `/me` to report `not_granted`). Renewal sends no `scope`, so it keeps the original grant; the device flow refuses a verification URL off the issuer's origin before printing anything. `verify` (required; the CLI checks `/me`) runs on the new login before it is stored and made the default, and `login` returns its result, so a rejected login never replaces the previous default. The browser flow listens on the first free port of `CALLBACK_PORTS` (52817, 54631, 57493, 61287): Auth0 matches loopback redirect URIs exactly, so each must stay registered as `http://127.0.0.1:<port>/callback` on the Auth0 command-line application, and changing the list is a change to that application. The browser (and the printed fallback) gets `http://127.0.0.1:<port>/start?n=<nonce>`, never the authorize URL, so `state` and the PKCE challenge stay off process command lines; the listener's lifecycle is one value, `_AwaitingStart | _AwaitingPick | _Picking | _Started` while listening and `_CodeReceived | _AuthorizationRefused | _StartedTwice` when done. `/start` with the nonce redirects to the authorize URL once; a second one ends the login with `LoginError`, before any token request. With `PickScopes`, `/start` instead serves the picker page (`_Picking`, carrying a second one-time nonce) and only a form POST to `/scopes` with that nonce and an accepted choice redirects (303) to the authorize URL; a wrong, missing or duplicated nonce or a GET gets 404, a choice `_chosen_scopes` refuses (empty, unknown scope) re-serves the page with 400 and the same nonce, and a POST after the redirect gets 400; a `/start` while picking ends the login like a second `/start`. The page's CSP has no `form-action`, since browsers apply it to the redirects after the POST and the sign-in redirects on to the deployment's identity provider. A wrong nonce, or a `/callback` before `/start`, gets 404, and a callback without this login's `state` gets 400; the listener keeps waiting after both. Every page it answers with comes from `_login_page.login_page(outcome | ScopeForm)`: fixed text for each outcome (never anything from the request), and for the picker the advertised scope names, HTML-escaped, self-contained HTML served with `Content-Security-Policy: default-src 'none'; style-src 'unsafe-inline'`, and the outcome decides the status code. The CLI's `confirm` answers `--yes` only for questions without `foreign_audience`; with one, `--yes` raises `ConfigurationError` and the question must be answered at a terminal.
  - `whitson_pvt_sdk/cli/`: the `wpvt` Typer app. The `cli` extra is Typer and keyring; the `mcp` extra is `cli` plus FastMCP, for `wpvt mcp` only. `__init__.main` prints the install command when Typer is missing, and `wpvt mcp` does the same for FastMCP; `_app.py` is the root app that adds every group; `_output.py` is the only place that writes text for the user: `note`, `emit` and the failure line show control characters other than newline and tab (C0, DEL, C1) escaped as `\xNN`, so server text cannot drive the terminal (JSON output is left to JSON's escaping, and `wpvt api` writes the raw body as `curl` does); `reporting` also routes the `whitson_pvt_sdk` logger through `note`, or drops it with `--json`, since Python's last-resort handler would print it unescaped. `_report` is the one mapping from an error to its `ErrorKind`, and `_exit_code` from the kind to the exit code: `configuration` 2, `authentication` 3 (`LoginError`, `AuthError`), `network` 4 (`NoResponseError`), `server` 4 (any other `ResponseError`: 5xx, and 408 and 429 once retries run out; an unexpected response shape, also from the login server or `/auth/config`), `refused` 5 (`RequestRefusedError`, the 4xx that `http.raise_for_status` gives the API's refusals, so a script can skip the item), `error` 1 (any other `SDKError`, such as `CredentialStoreBusyError`). It also prints Pydantic models as JSON. The `--json` error on stderr is `ErrorReport` (`error`, `message`), or for a `ResponseError` its subclass `ResponseErrorReport`, which adds `status` and `request_id` (`null` when the response had no `X-Request-ID`); a command that re-raises a `ResponseError` with its own message passes `request_id` on. Data commands build `WhitsonPVTClient()` with no arguments and hold no business logic:
    - `_auth.py`: `wpvt auth`. `status` shows the server's reason for a refused credential (`ResponseError.server_message`, set by `http.raise_for_status` from the JSON body's `message`, never parsed further) and adds "Run `wpvt auth login`" for a stored login only when there is none; the note about `WHITSON_PVT_TOKEN` after a login appears whenever the variable is set, empty included, as `auth.resolve_credential` treats it. Its browser opener is `webbrowser.open` with descriptors 1 and 2 pointed at the null device for the call, so a browser it starts (which inherits them on Linux) cannot write to the terminal; the opener's return value still decides between "Opened a browser" and the printed link.
    - `_resources.py`: `list` and `get` for regions, wells, samples, projects, fluid models and black-oil tables (`bot`) from one table, `RESOURCES`; a row's `listing` is `TopLevel | Nested | Unpaged` (which parent option, whether it pages), `--all` uses `Paginator.iterate`, and `aliases` are extra command names for the same group, hidden from `wpvt --help` (`black-oil-tables` for `bot`). A new resource is one row.
    - `_export.py`: `samples export` (one directory per sample id: `index.json`, `sample.json`, `compositions/`, `experiments/`; no server string reaches a path) and `bot export`.
    - `_reports.py`: `reports export` and `reports import`.
    - `_calc.py`: `calc flash|saturation-pressure|phase-envelope`, one generic `Calculation` row each; the request comes from `RequestFile | SampleFeed`, chosen by `_request_origin`.
    - `_api.py`: `wpvt api`, the raw route call (`Call | ListRoutes | Describe`), `--paginate`, and route discovery from `/external/v2/docs/openapi.json`. Path confinement is not here: it is `http.external_path`, used by `HTTPTransport.request` and `WhitsonPVTClient.request`.
    - `_mcp.py`: `wpvt mcp`, imported lazily so other commands do not load FastMCP. A FastMCP stdio proxy (`create_proxy` over a `StreamableHttpTransport` to `<base_url>/mcp`) with `LoginBearer`, the `httpx2.Auth` adapter over `auth.BearerSource`, and the `X-PVT-Client: wpvt/<version>` header. It checks the backend with one `list_tools` before serving and never starts a login; `LoginBearer` turns a 401 it cannot renew past and a 403 from `/mcp` into `AuthError` (exit 3), since the MCP client drops the HTTP status of a failed POST. FastMCP answers every refusal on `/mcp` with a generic 401, so for a stored login refused after its one renewal `LoginBearer` asks `GET /external/v2/me` with the same token (no further renewal) and reports, in that order: the API's `server_message` when `/me` answers 401/403 with one; that the login works for the API but not for MCP when `/me` succeeds; otherwise the `wpvt auth login` hint. The probe lives only there. It stays separate from `CredentialAuth`: the SDK client must let a final 401/403 reach `_raise_for_status` (server message, `request_id`), while the proxy must raise, so the two share `BearerSource` and `set_bearer` but not the flow. Session pinning and local tools would attach in `_serve` (transport headers and a provider on the proxy).
- Never log, print or put a token, refresh token, authorization code or PKCE verifier in an error. Tests run against a temporary `XDG_CONFIG_HOME` with the keyring disabled (`tests/conftest.py`); keep it that way so no test touches a real store.
- `GET /me` and `GET /auth/config` are in the OpenAPI document (tagged Authentication, so `EXCLUDED_RESOURCES` keeps them out of the generated resources; `client.me.get()` in `v2/resources.Me` is the one way to call `/me`), but their models stay hand-written next to the generated `Caller` and `AuthConfig`, each with a comment saying why: `Identity` (`shared/models.py`) and `_oauth.AuthConfig` keep `role` and `scopes` as `str`, where the generated models have `Literal` types that would make every installed SDK fail `wpvt auth login` once the server adds a role or scope, and `_oauth.AuthConfig` validates the issuer as `SecureUrl` before login trusts the deployment.
- `HTTPTransport` owns the `base_url.rstrip('/') + /external/v2` prefix, timeouts, retries (decided by `_retry.retry_delay`, which waits at most `MAX_SERVER_DELAY_SECONDS` for a server-given delay and treats a negative or non-finite one as absent), error mapping, JSON parsing, bytes downloads, multipart uploads, and `request()`, the raw call for any route, whose path `external_path` confines to the prefix (unreserved characters per segment, no `.`/`..`, no host, percent-encoding or query).
- Python 3.11 is the minimum; development and CI use 3.15 (`.python-version`). Do not use syntax newer than 3.11.
- Public resource classes in `whitson_pvt_sdk/v2/resources.py` usually re-export generated facades from `whitson_pvt_sdk/_generated/v2/resources.py`; put manual SDK conveniences there by subclassing/wrapping generated classes.
- Generated resource methods use SDK-shaped names (`list`, `get`, `create`, `update`, `create_bulk`, `update_bulk`) while lower-level generated module functions keep OpenAPI operation IDs.
- v2 list endpoints use paginated models for regions/projects/fluid models/black oil tables/wells.
- Report import/export is special: export returns raw zip bytes plus a synthetic filename, and import/preflight upload `archive.zip` with optional `meta_data` serialized from `ImportArchiveOptions`.
- The agent skill ships in the wheel at `whitson_pvt_sdk/.agents/skills/whitson-pvt/SKILL.md` (Library Skills layout); keep it in step with the public API. It is the single source: `plugins/wpvt/skills/` is a copy made by `just plugins-sync`, and `just lint` fails (`just plugins-check`) until the copy matches.
- `plugins/wpvt/` is the Claude Code and Codex plugin (this repository is its marketplace: `.claude-plugin/marketplace.json` and `.agents/plugins/marketplace.json`). Each tool has its own manifest and MCP file there (`.claude-plugin/plugin.json` and `.mcp.json`; `plugin.json` and `mcp.json` in the Agent Plugins format Codex reads); the plugin holds no deployment URL, token or version, and is not part of the wheel. Its icon, `assets/icon.png`, is a copy of the web app's 512 px icon; `.claude-plugin/plugin.json` names it in `icon`, and `plugin.json` in `extensions.com.openai.interface` (`logo`, `composerIcon`).
- Configure retries and timeouts on `WhitsonPVTClient(...)` with `RetryConfig`, `timeout`, and `file_timeout`; default retries apply only to `GET`/downloads and retry `408`, `429`, `500`, `502`, `503`, and `504`; a `429` is retried for every method.

## Endpoint Wrappers

For new endpoint wrappers or generator behavior:

1. Prefer changing `scripts/sdk_generator/` and regenerating over hand-editing generated endpoint/resource files.
2. Call `HTTPTransport.get`, `post`, `put`, `patch`, `delete`, `get_bytes`, or `post_multipart`.
3. Serialize Pydantic inputs with `model_dump(exclude_unset=True)`.
4. Validate structured responses with the generated model's `model_validate`.
5. Add or update the matching generated resource facade method through generator inference or `OVERRIDES` when the endpoint exists in OpenAPI.

For SDK-only conveniences or compatibility shims that are not OpenAPI-derived, add them to `whitson_pvt_sdk/v2/resources.py`, not `_generated/**`.
